# Контракт API ReleaseDesk

Курс: Б1.В.ДЭ.01.02.02 · КГЭУ · 2026/2027 · ЛР2  
Студент: Шафиков Тимур Фидаилевич · Группа: ТРИС-3-23

Базовый адрес: `http://localhost:5000`. Тела запросов и ответов — JSON. Статусы в JSON только `New`, `InProgress`, `Closed`, `Cancelled`. Метода `DELETE` нет: отмена — это статус `Cancelled`.

## Таблица запросов

| Метод и путь | Кто вызывает | Тело | Успех | Возможные ошибки |
|--------------|--------------|------|-------|------------------|
| `GET /api/releases` | все роли | — | `200`, массив заявок или `[]` | — |
| `GET /api/releases/{id}` | все роли | — | `200`, одна заявка | `404` нет такой заявки |
| `POST /api/releases` | менеджер проекта | `title`, `storeId`, `description` | `201`, заявка с `id`, `number`, `status: "New"` | `400` неверные поля или нет такого магазина; `403` роль не менеджер |
| `PATCH /api/releases/{id}/assignee` | менеджер проекта | `assigneeUserId` | `200`, заявка с исполнителем | `400` пользователь не релиз-инженер; `403` роль не менеджер; `404` нет заявки; `409` заявка не в статусе `New` |
| `PATCH /api/releases/{id}/status` | назначенный релиз-инженер; менеджер — только `Cancelled` из `New` | `status` | `200`, заявка с новым статусом | `400` неизвестный код статуса; `403` чужая заявка; `404` нет заявки; `409` переход запрещён правилами |
| `GET /api/stores` | все роли | — | `200`, список магазинов для выпадающего списка | — |

Пустой список — это `200` и `[]`, а не `404`.

При создании клиент **не присылает** `id`, `number`, `status`, `createdByUserId` и `assigneeUserId`: их определяет сервер.

Назначение и смена статуса — два разных `PATCH`. Назначение не меняет статус, смена статуса не меняет исполнителя.

## Разрешённые переходы статусов (`PATCH …/status`)

| Из | В | Кто | Иначе |
|----|---|-----|-------|
| `New` | `InProgress` | назначенный релиз-инженер | `409`, если исполнитель не назначен; `403`, если чужой |
| `InProgress` | `Closed` | назначенный релиз-инженер | `403`, если чужой |
| `InProgress` | `Cancelled` | назначенный релиз-инженер | `403`, если чужой |
| `New` | `Cancelled` | менеджер проекта | — |
| `Closed`, `Cancelled` | любой | никто | `409` |

## Примеры JSON

### `POST /api/releases`

Запрос:

```json
{
  "title": "Мобильный банк 3.4.1 — обновление",
  "storeId": 1,
  "description": "Исправлен вход по биометрии. Сборка: build #512 в GitLab. Выпустить до 30.10."
}
```

Ответ `201 Created`:

```json
{
  "id": 17,
  "number": "REL-2026-0017",
  "title": "Мобильный банк 3.4.1 — обновление",
  "description": "Исправлен вход по биометрии. Сборка: build #512 в GitLab. Выпустить до 30.10.",
  "status": "New",
  "storeId": 1,
  "createdByUserId": 2,
  "assigneeUserId": null,
  "createdAt": "2026-10-23T10:15:00Z"
}
```

Ответ `400 Bad Request` (короткий заголовок):

```json
{
  "errors": {
    "title": ["Заголовок должен быть от 5 до 80 символов"]
  }
}
```

### `GET /api/releases`

Ответ `200 OK`:

```json
[
  {
    "id": 17,
    "number": "REL-2026-0017",
    "title": "Мобильный банк 3.4.1 — обновление",
    "status": "InProgress",
    "storeId": 1,
    "createdByUserId": 2,
    "assigneeUserId": 5,
    "createdAt": "2026-10-23T10:15:00Z"
  }
]
```

### `PATCH /api/releases/17/assignee`

Запрос:

```json
{ "assigneeUserId": 5 }
```

Ответ `200 OK`: заявка целиком, `"assigneeUserId": 5`, `"status": "New"` (статус не изменился).

Ответ `409 Conflict` (заявка уже `Closed`):

```json
{ "error": "Нельзя назначить исполнителя: заявка в статусе Closed" }
```

### `PATCH /api/releases/17/status`

Запрос:

```json
{ "status": "InProgress" }
```

Ответ `200 OK`: заявка целиком, `"status": "InProgress"`.

Ответ `403 Forbidden` (другой релиз-инженер):

```json
{ "error": "Менять статус может только назначенный исполнитель" }
```

Ответ `409 Conflict` (переход `Closed` → `InProgress`):

```json
{ "error": "Переход Closed → InProgress запрещён" }
```

### `GET /api/stores`

Ответ `200 OK`:

```json
[
  { "id": 1, "name": "Google Play" },
  { "id": 2, "name": "App Store" },
  { "id": 3, "name": "RuStore" },
  { "id": 4, "name": "AppGallery" }
]
```
